# Independent review, round 2: is `feat/vision-implementation` a usable alpha (or beta) of VISION.md?

**Date:** 2026-10-29 (round 2, filed as `review-2026-10-30`). **Commit reviewed:** `0c40505` (phase 12). **Previous review:** [`review-2026-10-29.md`](review-2026-10-29.md) against `16f98a0`. **Scope:** read-only. I verified the earlier items against the code and by running things: `pnpm check`, contract drift, the Go server driven over HTTP and SSE on the local runtime, on the Anthropic runtime against a scripted fake Messages API, and in token mode, plus the built client driven in real headless Chromium. This file is the only one written.

## Verdict: **alpha** (not yet beta)

Every blocking item from the first review is fixed, and I verified each one live:

- The display renders.
- Enter no longer confirms a proposal while sending a message.
- The dev-mode auth bypass and cross-site requests are closed.
- Failures are visible and spoken.
- A reload no longer re-speaks the backlog.
- A real-browser smoke test runs inside `pnpm check`.

Phase 12's main claims also hold:

- Speech is published sentence by sentence while the model streams.
- The CSP has no `'unsafe-eval'`.
- The Anthropic runtime runs end to end through the real binary: streaming text, tool rounds, `show_ui` with per-op rejection fed back to the model, gated tools becoming proposals, cancel, and HTTP errors.

The owner can clone this on a Mac and use it in Chrome:

1. `pnpm install`
2. `pnpm -C client build`
3. `go run ./cmd/api`

Without a key that gives the local demo; with `ANTHROPIC_API_KEY` set it talks to Claude.

It is not a beta for four reasons:

- **It has never talked to a real model.** The live check exists, but nobody has run it, and the VISION 7 decision is still open.
- **Voice, half the product, has never run on a Mac with a microphone and speakers.** Reading the code shows several races in playback and mic handling that only real use will expose.
- **One failed turn makes the screen say "connection lost" until a reload, and again on every reload after that.** This is a new, one-line bug: the server names an SSE event `error`, and `EventSource` reports that as a connection error.
- **CI is red on both phase 11 and phase 12.** The contract-drift check passes only on the authors' machine.

## Blocking gaps for beta (in order)

Items 1 and 3 are cheap and worth fixing before the owner's first session, even at alpha.

1. **A false "connection lost · reconnecting" banner after any server `error` event, and again after reloads.** *(new; verified in Chromium)*
   - **Cause:** the server streams runtime failures and rejected ops as SSE events of type `error` (`httpsrv/events_handler.go` `writeSSE`; event type list in `client/src/session/stream.ts:16-30`). An `EventSource` dispatches a named `error` event to `onerror` as well as to `addEventListener("error")`. `stream.ts:87-95` then sees `readyState === OPEN` and sets the connection to `reconnecting`.
   - **Live result:** one `badmodel` turn through the Anthropic fake flipped the header from `ONLINE · DEV` to `RECONNECTING` and showed the red `CONNECTION LOST · RECONNECTING` banner. It stayed there 20 s later and after the next successful turn.
   - **Reload:** the bus replays up to 1000 buffered events, so every reload re-fires the old `error` events and the banner comes back. I saw nine `error` dispatches on one reload.
   - **Why it matters:** with Claude, rejected `show_ui` ops are routine, so the always-on screen will claim to be offline most of the time. The banner also sits over the top-centre UI zone.
   - **Same root, second symptom:** a genuine network error delivers a plain `Event` to the same message handler. `parseEvent(undefined)` returns null, and then `e.data.slice(0, 120)` throws (`stream.ts:99`). The first browser run logged `pageerror: Cannot read properties of undefined (reading 'slice')`.
   - **Fix:** rename the wire event (for example `runtime_error`; it is a contract change, so regenerate), or ignore `MessageEvent`s in `onerror`. Guard `e.data` in the handler. Add a smoke-test step that drives a failing turn and asserts the header stays `online`.

2. **No live model run, and the VISION 7 decision is still open.** *(carried over)*
   - **What exists:** `cmd/runtime-check` and `scripts/anthropic-live-check.sh` are good. Against my fake they print a readable table, and with no key they exit 2 with the key diagnosis. The request goldens are clear.
   - **What has not happened:** nobody has run them against `api.anthropic.com`, so `docs/executing/spikes/` holds only the local report.
   - **Untested wire choices:** two things the goldens record can only be confirmed live:
     - SDK v2.4.0 sends the API key as `Authorization: Bearer` rather than `x-api-key`. I confirmed this on the wire to my fake.
     - Every request carries the `server-side-fallback-2026-07-01` beta and `fallbacks: "default"` by default.
   - **Fix:** the owner's first step with a key is `scripts/anthropic-live-check.sh`. Commit the spike report and record the VISION 7 decision.

3. **The mic can stay live while the indicator says off.** *(new; read line by line, not run: no microphone here)*
   - **Where:** `voice/controller.ts:172-221`. `openMic` awaits `getMicStream`, and only then assigns `this.capture`.
   - **Trigger:** a push-to-talk tap shorter than `getUserMedia`, or a second Ctrl+Space or Ctrl+M while the macOS or Chrome permission prompt is open. Either runs `closeMic()` while `capture` is still null.
   - **Result:** the capture then starts with the state `off`. VAD still barges in, transcribes and sends turns, and the next Ctrl+Space creates a second capture, which sends duplicate turns.
   - **Scope:** the server-STT path (`OPENAI_API_KEY` set) and browsers without `SpeechRecognition`.
   - **Why it ranks here:** an always-on office screen that records while saying "mic off" is a privacy defect.
   - **Fix:** after the await, re-check the activation state or a generation counter, and stop the stream if the mic should be closed.

4. **The speech queue is fragile under barge-in and on an always-on screen.** *(new; read, not run)*
   - **In-flight audio survives stop:** `ServerSpeech.speak` (`voice/playback.ts:109-136`) awaits `/api/voice/tts` before it sets `current`, so `stop()` during the fetch does nothing. The stale sentence plays anyway.
     - If more speech was queued meanwhile, a second drain runs and two sentences overlap.
     - `this.meter` is overwritten, so a 33 ms level interval leaks for good, and the nebula's audio reaction drifts.
     - With per-sentence streaming, the fetch window is a large share of speaking time.
   - **No timeout:** `speak()` has none (`playback.ts:66-84`, `:156-192`). A `speechSynthesis` utterance whose `onend` never fires wedges the queue. Chrome is known to garbage-collect utterances held only by their own handlers, and `u` is referenced only by its own handlers.
     - The scene then shows "speaking" forever.
     - With `CORELLIA_VOICE_BARGE_IN=off`, every voice input is ignored from then on (`controller.ts:109`).
   - **Escape does not silence the agent once the turn is done.** Most speech plays after `turn_done`, and Escape with no active turn clears the screen instead (`renderer/useGlobalKeys.ts:35-39`, `app/App.tsx:107-109`). The comment at `controller.ts:106` says Escape interrupts. No Escape path calls the player's stop.
   - **Fix:**
     - Pass a generation number or `AbortSignal` into `speak` and bail after each await.
     - Add a per-piece timeout and hold a reference to the utterance.
     - Make Escape stop playback first, then cancel, then clear.

5. **Failures are visible, but in raw form, and a dropped stream counts as success.** *(new; verified live against the fake)*
   - **Raw error everywhere:** a model 404 or 529 produced this apology:

     > Sorry, that didn't work on my side. anthropic: POST "http://127.0.0.1:18191/v1/messages": 404 Not Found {"type": "error", "error": {"type": "not_found_error", …}}

     The speech queue reads that out, URL and JSON included, and the same text appears in the Status card, the transcript and the error line (`session.go:671-680` `failureReply`). It also goes into the history sent to the model on the next turn (I saw it in the next request body).
     - **Fix:** map runtime errors to a short spoken reason, as `cmd/runtime-check`'s diagnosis already does. Keep the detail in the log and `?debug=1`, and leave failed apologies out of model history.
   - **Truncated stream treated as complete:** I had the fake close the connection mid-reply, with no `message_delta` and no `message_stop`. The turn ended `status: completed` with the half sentence as the full answer.
     - The cause is in `runtime/anthropic/anthropic.go`: a stream that ends without a stop reason falls through `StopReason != tool_use` and returns nil.
     - The same applies to a tool call cut mid-input: it is silently never run.
     - **Fix:** treat an empty `StopReason` as an error.

6. **The Mac acceptance run with microphone and speakers has not happened.** *(carried over)*
   - Phase 8's acceptance line is still pending: speech start latency, barge-in, the `speechSynthesis` gaps between streamed pieces, and Ctrl+Space against macOS input switching.
   - Items 3 and 4 are the kind of thing that run will expose.
   - **Defaults to revisit:** `CORELLIA_VOICE_BARGE_IN` defaults to `auto`, and with VAD any noise (a cough, a door) cancels the running turn (`controller.ts:97-100`). On laptop speakers the agent's own voice interrupts it; `speechSynthesis` output bypasses Chrome's echo cancellation.
   - Consider `off` (or push-to-talk) as the Mac default until the run is done.

7. **CI is red, so "drift-tested" holds only on one machine.** *(new; from `gh run view`)*
   - **Status:** both pushed runs failed: `40915876689` (phase 11) and `40922314529` (phase 12).
   - **Contract job:** `scripts/contracts-generate.sh:17-21` installs `go-jsonschema@v0.20.0` only when no binary exists. The committed Go types were generated with a locally installed **v0.24.1** (I checked with `go version -m`). On CI, or on the owner's Mac, `pnpm contracts:generate` produces different Go code: `omitzero` tags and a missing `ErrorEvent.Error` field.
     - **Fix:** run the pinned version (`go run github.com/atombender/go-jsonschema@vX`) and regenerate.
   - **Smoke job:** `playwright install --with-deps chromium-headless-shell` fails with "Playwright does not support chromium-headless-shell on ubuntu26.04-x64", because `ubuntu-latest` has moved.
     - **Fix:** pin `runs-on: ubuntu-24.04` or upgrade Playwright.
   - **What passed:** the backend job, including `go test -race`, so the race detector has now run once and passed.

8. **Generated UI collides with itself.** *(new; screenshots from Chromium)*
   - **Top-right pile-up:** the server puts several overlays at `top_right` with no stacking: the reply card (`reply_card`), the error Status card (`status_card`), the reminder confirmation (`status_reminder`) and the clock glance. They render on top of each other and the text is cut off.
   - **Bottom overlap:** the 12-second error line overlaps the last transcript entry.
   - **Top-centre overlap:** the offline banner sits over the root UI at the top centre.
   - **Fix:** apply the proposals fix (one overlay holding a `Stack`) to every server-originated glance card, and give the error line its own row.

## Non-blocking gaps

### New, client (from a read-only pass over `client/src`; the items marked verified I traced myself)

- **Holding Enter after sending a message confirms the pending proposal.** The first keydown submits and calls `preventDefault`. The auto-repeat keydown then sees an empty input and fires the Confirm card's `enter`. `useGlobalKeys.ts:52-62` never checks `e.repeat`. *(verified)* Ignore repeats for Enter, Escape and digits.
- **Digit hotkeys reach "Do it" on proposals below the top one.** Only the top card gets Enter and Escape (`proposals.go:190-193`), so the renderer numbers the others. A message that starts with "1", followed by a pause longer than 350 ms, confirms a side effect. Keep digits off `confirm_proposal` actions.
- **Digit edge cases:**
  - A digit followed by Enter within 350 ms sends "1" as a paid turn.
  - Any spec change during the grace period cancels a pending digit.
- **Voice capabilities are fetched once, at init** (`voice/controller.ts:73-84`). If the page loads before the backend is up, or before a token is entered, the server's STT and TTS and `barge_in=off` stay unused until a reload.
- **The 3D agent has no error boundary.** `Agent3D` sits outside the stage `ErrorBoundary` (`renderer/Stage.tsx:104-105`), and there is none at the root. If WebGL context creation fails after a GPU-process crash or sleep/wake, or the `Nebula` chunk fails to load, the page goes blank.
- **Browser recognition and the mic indicator:**
  - A `network` error is treated as fatal (`voice/browserStt.ts:33`), but the mic indicator keeps saying "listening". On an always-on screen, one blip ends recognition for good. Retry with backoff, and reset activation on fatal errors.
  - Chrome fires `speechstart` once per recognition session, so voice barge-in works only for the first utterance.
- **Push-to-talk:**
  - Cmd+Tab while holding Ctrl+Space leaves the mic open, because there is no blur handler.
  - The flush on key-up is VAD-gated, so short or quiet speech is dropped.
- **`ignoreUtterance` can stick** with `barge_in=off` (`controller.ts:108-123`) and drop the owner's next real utterance.
- **`Renderer` updates the store during render** (`renderer/Renderer.tsx:40` → `addError`). That gives a React warning in dev, and in every build the same error is appended again on each re-render.
- **Smaller client items:**
  - `pendingSpeech` is not reset on a snapshot or `turn_started`.
  - A Map in the failure path keeps its WebGL context until unmount.
  - `SessionStream` shares one `stopped` flag across connections.
  - The token prompt also appears for a 403 from the Origin or Host guard, which no token can fix.
  - A bound `Image.src` skips the server allowlist (the CSP covers it, but Vite dev serves no CSP).
  - Speech has no prefetch, so there is a TTS round-trip gap between sentences.

### New, backend and configuration

- **The SSE snapshot and its seq are read in two calls** (`events_handler.go`: `Snapshot()`, then `Seq()`). An op published in between can be in neither the snapshot nor the replay the client accepts. The window is tiny.
- **The Anthropic SDK reads its own environment variables,** bypassing `internal/config` (rule 4): `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_CUSTOM_HEADERS` and `ANTHROPIC_PROFILE` (`anthropic-sdk-go/v2@v2.4.0/client.go:58-130`). I used `ANTHROPIC_BASE_URL` to point the real binary at my fake.
  - On a Mac shell with a gateway URL exported for other tools, Corellia would silently follow it.
  - Pass `option.WithoutEnvironmentDefaults` plus explicit options, or document the variables in `config`.
- **The high-risk voice hold is unexercised.** No registered tool has `Risk: "high"`; `forget`, `set_reminder` and `open_directions` are all `low`.
- **`open_directions` asks for confirmation** although it only shows a map.
- **The directions origin is hard-coded to Lisbon** (`tools/builtin/builtin.go:433`, "Office"), and there is no config for the office location.
- **A cancelled turn's partial reply still goes into model history** (verified in the next request body). This was carried over from the first review. Defensible, but unaddressed.
- **Default `CORELLIA_DEV_ORIGINS=http://localhost:5173`** is allowed with CORS in token mode too. Any local dev server on Vite's default port can drive the agent. The risk is low, but clear the default when a token is set.
- **File modes differ:** `reminders.json` is written 0600 and `transcript.jsonl` 0644.

### Carried over, still open

- **Catalog fit-ranking** still does not narrow the prompt (documented as deliberate).
- **The local runtime is a scripted demo,** and the header now says **local demo**. Re-verified:
  - "Ulaanbaatar" shows Lisbon.
  - "weather today" shows the sample schedule.
  - "remind me at 9" and "remind me in 5 minutes" both propose 17:00, with the whole sentence as the reminder text.
- **Ctrl+Space** is not configurable (macOS input-source switching).
- **Docker image, `box/` scripts, OpenAI audio and Hermes** have not been run live.
- **Short spoken confirm phrases** still confirm the newest low-risk proposal for its 2-minute TTL. As designed; low risk while no tool has external side effects.
