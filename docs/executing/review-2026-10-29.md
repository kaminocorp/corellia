# Independent review: is `feat/vision-implementation` a usable alpha of VISION.md?

**Date:** 2026-10-29. **Commit reviewed:** `16f98a0` (phase 10). **Scope:** read-only review of the whole repo against [`../VISION.md`](../VISION.md) and [`roadmap.md`](roadmap.md). The only file written is this one.

## Verdict: **not ready** (it will be an alpha after the blocking fixes below)

The backend is real and well-built. The contract is shared and drift-tested, every op is validated server-side, and propose/confirm, persistence, reminders and proactivity all work when driven over HTTP and SSE. The client is a different story: **its main view does not render at all.** `Display` subscribes to the store through `useSyncExternalStore` with a selector that returns a new object on every call. React 19.2.4 then aborts with "Maximum update depth exceeded" (error #185), and the root stays empty. I reproduced this by mounting the real `App` in jsdom with the client's own React, and with a minimal copy of the pattern in both dev and prod builds. It is React behaviour, not a jsdom artifact. Nobody can open the product on a Mac and use it, so the phase notes' claim of "complete" is not supported. The client has never run in a browser: the completion notes for phases 3, 4, 5 and 8 each say so, and no test mounts `App`. Fixing the crash will expose a second layer of client bugs that only a real browser shows. One of them undermines the propose/confirm guarantee: pressing Enter to send a message also confirms the pending proposal. There is also a dev-mode auth bypass, and dev mode is how the README tells the owner to run it. All of these are fixable in a focused pass. None calls for redesign.

## Blocking gaps (in order)

1. **The display renders a blank page.** In `client/src/session/store.ts:194`, `useSessionState` passes `() => selector(getState())` as `getSnapshot`. The selectors at `client/src/app/App.tsx:38`, `app/Transcript.tsx:8` and `app/DebugPane.tsx:5` return fresh object literals, so React loops and unmounts the tree. `?gallery=1` does not use the store and is unaffected.
   *Fix:* select one primitive or stable field per `useSessionState` call, or use `useSyncExternalStoreWithSelector` (from `use-sync-external-store/with-selector`) with `shallowEqual`. Then add a vitest that mounts `<App />` with a fake `EventSource` and `fetch` and asserts that the input renders. That test would have caught this.

2. **There is no browser smoke test, and no run in a real browser has ever happened.** All 120 client tests are unit tests. After fixing #1, open the app in Chrome on macOS and go through the roadmap acceptance lines for phases 3, 4, 5 and 8: streaming text, Lisbon map tiles, nebula fps with `?stats=1`, mic toggle, `speechSynthesis`, barge-in.
   *Fix:* add a Playwright smoke test to `pnpm check` that loads `/`, `/?gallery=1` and `/?debug=1` against the Go server and fails on any console error. This could not run in this environment: the cached headless Chromium is missing X11 and GTK libraries.

3. **Enter sends the message and confirms the pending proposal in the same keystroke** (breaks rule 5). `CommandInput.onKeyDown` (`app/CommandInput.tsx:45-52`) calls `setValue("")`, which calls `onValueChange` synchronously and sets `inputValue.current = ""` (`App.tsx:123-126`). Then the window listener in `renderer/useGlobalKeys.ts:32` runs, sees an empty input and fires the Confirm card's `enter` action (`backend/internal/session/proposals.go:162`). So typing "what's the weather" and pressing Enter while a reminder or `forget` is pending executes it.
   *Fix:* ignore `e.defaultPrevented` in the global handler, or record "input was empty" at keydown before the input handler clears it. Add a test that types text, presses Enter with a pending proposal, and asserts that nothing is confirmed.

4. **In dev mode, the loopback-only check can be bypassed, and the API accepts cross-site requests.**
   - `httpsrv/server.go:52` installs `middleware.RealIP` before `auth.Middleware`. That rewrites `RemoteAddr` from `X-Forwarded-For`, `X-Real-IP` or `True-Client-IP`, so `auth.isLoopback` trusts a header the client controls. I verified it live: from a non-loopback interface, `/api/config` returns 403, and the same request with `X-Forwarded-For: 127.0.0.1` returns 200. With that header, `POST /api/turn` returned 202.
   - The server binds `:PORT` on all interfaces, and there is no host setting.
   - `POST /api/turn` accepts a `text/plain` body. Combined with no auth in dev mode, any web page open in the owner's browser can drive the agent with a simple CORS request (no preflight), including saying "yes" to confirm a pending proposal. Chrome's local-network-access protections may block some of these, but nothing in the app does.
   - Nothing checks the `Host` header, which leaves the door open to DNS rebinding.

   *Fix:*
   - Drop `RealIP`, or apply it only behind a configured trusted proxy.
   - Bind `127.0.0.1` when no token is set, and add a `CORELLIA_BIND` setting.
   - Require `Content-Type: application/json` on POSTs.
   - Reject requests whose `Origin` is set and not allowed, and in dev mode reject a `Host` that is not loopback.

5. **Failures are invisible, and the cloud runtime has never run live.**
   - A runtime failure produces an `error` event and an empty `turn_done` (`session.go:379,427`). The client shows errors only under `?debug=1`. I verified this with an upstream HTTP 500 through the `openai` runtime: the user sees their own message and nothing else, and hears nothing.
   - The Anthropic runtime, which the owner will actually use, has only been run against recorded fixtures. It sends the beta server-side-fallback parameter (`runtime/anthropic/anthropic.go:174-177`) with `claude-opus-5-5` by default. If the account or API rejects any part of that request, every turn fails silently.

   *Fix:*
   - Show the latest error in the transcript or status line, and say a short apology on fatal errors.
   - Add `CORELLIA_ANTHROPIC_FALLBACKS=false` as an escape hatch.
   - Run `go run ./cmd/runtime-spike -runtime anthropic` with a real key before handing it over, and commit the report.

6. **Opening or reloading the page re-speaks old replies.** On first connect there is no `Last-Event-ID`, so the bus replays up to 1000 buffered events (`events_handler.go:32-43`, `BusCapacity` 1000). The reducer drops them by seq, but `session/stream.ts:75-76` still calls `onEvent` for each one. That reaches the voice controller (`voice/controller.ts:87`), which queues every past `speech` event. With speech on, a reload reads out the backlog. In normal Chrome, the queue stays stuck until the first key press (see the autoplay item below) and then plays all at once.
   *Fix:* forward to `onEvent` only events with `seq` greater than the snapshot seq.

## Non-blocking gaps

### Product and UX

- **Speech starts only when the turn has finished.** The decision layer runs in `finish()` (`session.go:343-372`), so every `speech` event is published just before `turn_done`. I measured it live: the first text delta came at 15:19:40.652 and all three speech events at 15:19:41.285, the same instant as `turn_done`. Phase 8 promised "audio starts before the turn ends", and VISION 7 makes time to first audible response criterion 1. With Opus and tool rounds, that means seconds of silence. Segment and publish speech as sentences complete.
- **`show_ui` tells the model "Displayed N ops." even when the server rejected some of them.** Validation happens in `session.applyOp`, after `toolexec.Run` has already returned the tool result. Live, with `javascript:` and `Iframe` ops in the batch, the model got "Displayed 8 ops." while three ops were dropped and the root card was left with dangling slot refs. The model gets no chance to repair. Validate inside the tool and return the per-op errors.
- **The local runtime is a scripted demo, and it fails without saying so.** Verified live:
  - "show me a map of Ulaanbaatar" shows Lisbon. Only 12 cities are in the gazetteer.
  - "what's the weather today" shows the hardcoded sample schedule, because the `today` intent comes before `weather`.
  - "remind me at 9 to call Ana" proposes 17:00, with the whole sentence as the reminder text.

  This is fine as a keyless demo, but the UI should say "local demo runtime" visibly. Then the owner can tell scripted output from real output. The committed spike report (`spikes/local-2026-10-29.md`, 100% first-try validity) says nothing about the VISION 7 decision.
- **Agent speech outside a turn never reaches the transcript.** This covers confirm results, "That didn't work…" and tool or proactive replies. `sayAndRecord` (`proposals.go:234`) publishes only `speech`, and the client adds transcript entries only on `turn_started`/`turn_done`. With TTS off or blocked, the owner cannot see what a confirmed action did.
- **Two pending proposals stack exactly on top of each other** (both at `bottom_right`, both bound to Enter/Esc). `byKey` picks the first in sorted order (`useGlobalKeys.ts:19`), which can be the card underneath.
- **A message cannot start with a digit while numbered actions are on screen,** for example "10 minute timer" (`useGlobalKeys.ts:26`).
- **Typing the first character of a follow-up cancels the running turn** (`App.tsx:124` → `bargeIn`).
- **Short replies confirm the newest pending proposal for its whole 2-minute TTL.** That covers "ok", "sure", "yes please" and similar (`proposals.go:27-31`). With an open mic and echo, background speech can confirm. Today's gated tools only touch Corellia's own store, so the risk is low now and will grow with real side-effect tools. Consider requiring a key press for `risk: high`.
- **Mac shortcut collisions.**
  - Ctrl+Space is the default "select previous input source" shortcut once more than one input source is enabled.
  - `activation.ts:26` also accepts Cmd, so Cmd+Space opens Spotlight and Cmd+M (mute) minimizes the window.

  Drop `metaKey` and offer a configurable key.
- **Long content is clipped.** The UI zone is `overflow-hidden` with no scroll and no paging (`renderer/Stage.tsx:40`). The footer transcript (6 entries, unbounded length) overlaps panels at bottom centre.
- **Whitespace-only text starts a turn,** which is a paid cloud call. Verified: `{"text":"   "}` returned 202.
- **The nebula never shows `speaking` during playback.** The server goes idle at `turn_done` while TTS is still playing, and audio only modulates the scene in the `speaking` state (`agent3d/state.ts:95`; `App.tsx:102` ignores `voice.status.speaking`).
- **`proactive` events and `pending_proposals` from the snapshot are never rendered.** The cards still appear because the server also sends them as spec ops. `confirmProposal`/`rejectProposal` in `session/api.ts:57-65` are dead code.

### Voice (unverified in any browser; found by reading the code)

- **Autoplay.** The `AudioContext` is created lazily at the first speech (`voice/playback.ts:88-91`). In normal Chrome on a Mac (no kiosk autoplay flag), it stays suspended until a user gesture, and `speak` has no timeout, so the queue stalls. Create and resume it on the first keydown.
- **Voice is dead under Vite dev (`:5173`).** StrictMode's effect cleanup calls `dispose()` (`voice/useVoice.ts:27-33`), and the second `init()` returns early because of `disposed` (`controller.ts:73`). The production bundle is unaffected, because StrictMode double-invokes effects only in development.
- **Self barge-in.** Speech-start events cancel playback (`controller.ts:141-156`). On laptop speakers, the agent's own voice can interrupt itself or be transcribed as a user turn. Suppress speech-start while playing, or recommend headphones or `ptt` for Mac testing.
- **Push-to-talk throws away the utterance being spoken at key-up** (`voice/capture.ts:92-95`, `discardNext`).
- **Browser recognition restarts in a tight loop after fatal errors** such as `not-allowed`, `network` or `audio-capture` (`voice/browserStt.ts:68-76`).

### Session and transport

- **The SSE stream can close for good.** `EventSource` gives up on any non-200 response, and there is no reconnect of our own (`session/stream.ts:65-68`). That covers a 401 from a wrong token, a 403, and the 500 the Vite proxy returns while `air` restarts the backend. The banner then says "reconnecting" forever. A plain connection-refused does retry. Reconnect with backoff when `readyState === CLOSED`, and show auth failures as their own message.
- **Token handling is bare.** The token comes only from `?token=` (`session/auth.ts:16`). It stays in the URL bar and in history, there is no way to enter it in the UI, and a wrong token looks like "backend unreachable". The kiosk script also puts it in the URL.
- **Decay timers restart on every reconnect** (`store.ts:91`).
- **The error boundary resets on every parent render,** because `children` is a new object each time (`app/ErrorBoundary.tsx:22`).

### Rendering safety (backend validation held in every live test)

- **`Image` accepts any `https://` host** (catalog pattern `^https://\S+$`), so a prompt-injected model can make the display fetch `https://attacker/leak?d=…`. Verified live: the op was accepted and forwarded. Add a host allowlist or proxy images, and serve a CSP header. There are no security headers today.
- **Map instances can leak WebGL contexts.** `Renderer.tsx:58` calls component implementations as plain functions, and the root `NodeView` has no key (`:21`). MapLibre's cleanup may then never run. On an always-on screen this can eventually exhaust Chrome's roughly 16 contexts and kill the nebula. Render `<Impl/>` and key the root by node id.
- **One failed tile hides the map for good** (`components/Map.tsx:59-61`; `failed` never resets).

### Configuration and deploy

- **`auto` can silently switch the runtime.** If only `OPENAI_API_KEY` is set, intended for voice as the README suggests, `auto` selects the `openai` runtime with `gpt-4o-mini` (`rtselect/select.go:22-28`). The README says that key "adds server speech recognition and synthesis" and does not mention the switch.
- **Reminders use the server's local time zone** (`time.Local`). The Docker image installs `tzdata` but sets no `TZ`, so a containerised backend fires "17:00" in UTC. Document `TZ` or make it a config value.
- **`Confirm` overwrites session state** (thinking, then idle) even while another turn is active (`proposals.go:180-208`).
- **On cancel, the partial reply is stored in the transcript and history** (`session.go:343-353`, inside `finish`).
- **`truncate` slices bytes** (`session.go:598`) and can split UTF-8 characters in summaries and reply cards.
- **The Mac run path works as documented:** `pnpm install`, `pnpm -C client build`, `go run ./cmd/api` serving the bundle. macOS will show a firewall prompt because the server binds all interfaces, which item 4 above fixes.
- **The Docker image and `box/` scripts were not built or run here:** there is no Docker socket and no Debian hardware. The box files are untested by the authors' own admission. `provision.sh --with-backend` expects the binary and client to already be in `/opt/corellia` (this is documented in `box/README.md`).
- **There is no CI workflow,** and the race detector was never run: no cgo or C toolchain here, so `go test -race` fails to build. Run `-race` in CI.

## What I verified and how

**Build and tests (all green)**

- `pnpm install` and `pnpm check` exit 0: client type-check, lint (0 errors, 2 fast-refresh warnings), 23 files and 120 tests; Go vet and all packages pass.
- `go test -count=3 -shuffle=on ./...` passes. `-race` could not run (no cgo or C compiler).
- `pnpm -C client build` succeeds: main chunk 428 kB, Nebula 927 kB, maplibre 1.05 MB.
- `pnpm contracts:generate` followed by `git status` shows no drift.

**Live backend** (binary built to the scratchpad; `PORT=18090`, `CORELLIA_DATA_DIR=/tmp/corellia-review*`, `CORELLIA_CLIENT_DIR=client/dist`)

- **Dev mode:**
  - Loopback gets 200 and a non-loopback interface gets 403.
  - The same non-loopback request with an `X-Real-IP` or `X-Forwarded-For: 127.0.0.1` header gets 200, and with it a spoofed `POST /api/turn` was accepted (202).
- **Token mode:**
  - No token gets 401; `Authorization: Bearer` and `?token=` both work.
  - A `text/plain` POST with an evil `Origin` is accepted (202), and the preflight returns 401 with no CORS headers.
- **Local runtime, over SSE:**
  - Hello, time (live `get_time` tool), Lisbon map, table, chart, schedule, weather (live Open-Meteo call returned real data).
  - Cancel mid-turn gives `turn_done` with status `cancelled` and modality `none`.
  - Clear; routing mistakes as listed above.
- **Proposals:**
  - "remind me…" then "do it" by voice-sourced text confirms; "no, cancel" rejects.
  - `/api/action/confirm` returns 200, then 404 on a repeat; an unknown reject returns 404.
  - Past `HH:MM` rolls to tomorrow.
  - A proposal expired on schedule and its card was removed.
- **Proactivity:** a reminder set for the next minute fired at hh:mm:00 as a `proactive` event, an amber glance card and a `speech` event.
- **SSE:** `Last-Event-ID` replay is correct, a future id still gets the snapshot, and heartbeats arrive.
- **Persistence:** SIGTERM gives a graceful shutdown. After a restart on the same data dir, 37 transcript entries and 3 reminders were restored, and the history reached the model.
- **Cloud path:** restarted with `CORELLIA_RUNTIME=openai` pointed at a scripted fake `/chat/completions` server that streams tool calls (kept in the scratchpad, not the repo). Checked:
  - Tool calls split across chunks assembled correctly.
  - `show_ui` ops were applied.
  - `remember` stored a note, and the note appeared in the next system prompt (6.6 kB prompt, 9 tools).
  - `set_reminder` and `forget` became proposals with Confirm cards; `forget` executed after "yes".
  - Malicious ops were rejected: a `javascript:` Image (`invalid_props`) and an unknown `Iframe` component (`unknown_component`). A raw-HTML Markdown string was forwarded as text; the client renders it through an AST with no HTML.
  - Upstream 500 produced a fatal `error` event and a `failed` turn with no speech.
- **Input handling:** malformed JSON gives 400 and a missing `text` gives 400 (schema-validated). A 200 kB body gives 413 and a 5 kB text is accepted. `/api/voice/stt` and `/api/voice/tts` give 501 with clear codes when no provider is configured.
- **Spike:** `cmd/runtime-spike` ran for `local` and the fake `openai` runtime, with `-out` set to the scratchpad. It has no side effects on the repo.

**Client**

- Mounted the real `App` in jsdom with the client's React 19.2.4, using a vitest config and test file kept in the scratchpad. Result: empty root, "The result of getSnapshot should be cached", then "Maximum update depth exceeded". A minimal copy of the selector pattern fails the same way in React's production build (#185).
- A real-browser run was attempted but was not possible: the cached Playwright Chromium is missing system libraries.
- A separate read-only pass over `client/src` produced the client findings above. I checked the blocking ones myself in the code: #1 reproduced, and #3 and #6 traced line by line.
- **Confirmed sound in the client:**
  - No `dangerouslySetInnerHTML`, `innerHTML` or `eval`; Markdown is AST-only with no links.
  - Every SSE payload is validated with Ajv, and resolved props are re-validated before render.
  - The input autofocuses and takes focus back after blur.
  - WebGL and reduced-motion fallbacks exist.
  - The heartbeat is posted.

**Not verified:** any real browser behaviour (rendering, map tiles, WebGL fps, mic, speech), the Anthropic, OpenAI-audio and Hermes integrations against live services, the Docker image, and the `box/` provisioning.

All server, fake-model and SSE processes started for this review have been stopped. No code, config or other docs were changed.
