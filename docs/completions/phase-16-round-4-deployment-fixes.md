# Phase 16: Round-4 review, deployment fixes

**Date:** 2026-10-30. **Branch:** `feat/vision-implementation`. **Changelog:** 0.15.16. **Roadmap:** [`../executing/roadmap.md`](../executing/roadmap.md) Phase 16. **Input:** the fourth independent review ([`../executing/review-2026-10-30-round4.md`](../executing/review-2026-10-30-round4.md), against `6477d0f`, verdict "a beta on the Mac; not yet a deployable beta"), committed with this phase.

## Summary

The review found the Mac run a beta and the deployment paths (display box, Docker image, a backend reached over the LAN) not yet one, with three fixable defects on those paths and a handful of non-blocking items. This phase takes all of them: the model's clock now follows `CORELLIA_TZ`; a display on plain HTTP at a network address is told in the mic indicator that voice needs HTTPS or localhost, the kiosk marks its one origin as secure for Chromium, and the docs lay out the three topologies (backend on the box, HTTPS via `tailscale serve` or a reverse proxy, plain LAN HTTP); the kiosk unit owns tty1 alone and `box/release.sh` plus `provision.sh --release` install the binary and the client; a refusal after partial text is spoken separately and kept out of the history; prompt caching has a stable prefix and three breakpoints instead of a system block that changed every minute; a root `.dockerignore` keeps `backend/.env` and `backend/data` out of the build context; the watchdog restarts a kiosk that never loaded; the local demo's intent order and word boundaries are fixed; `docs/stack.md` names the real `Referrer-Policy`. Each change has a test, including the box scripts (`box/test.sh`, in `pnpm check` and CI).

No contract change. One addition to the runtime seam (`runtime.ErrRefused`, a sentinel like `ErrTruncated`), one to `session.Options` (`Location`), one to the client's `VoiceDeps` (`secureContext`). No config change; `CORELLIA_TZ` now means what `.env.example` said it meant.

## What was built

- **Item 3, the clock.** `session.Options.Location` makes the session's clock read in the configured zone; `cmd/api` and `cmd/runtime-spike` pass `cfg.Location()`. The prompt's "Current date and time" line, the transcript timestamps and everything else the session stamps now agree with `get_time`, the clock card and the scheduler, which already used it. Tests: `TestClockFollowsLocation` (session: the runtime sees `Asia/Singapore`, offset +08:00, and the prompt line carries `(+08)`), `TestTurnContextClockFollowsNowZone` (prompt: 23:59 UTC Thursday prints as Friday 07:59 in Singapore, the review's exact case).
- **Item 4, voice over plain HTTP.** Three layers:

Test: `controller.test.ts` ("explains an insecure context instead of opening the mic", both paths).
  - *Kiosk.* `corellia-kiosk.sh` derives the origin from `CORELLIA_URL` and, for a non-loopback `http://` URL, adds `--unsafely-treat-insecure-origin-as-secure=<origin>` (per profile, which `--user-data-dir` makes ours); `https://` and loopback URLs get no flag. `CORELLIA_KIOSK_PRINT=1` prints the Chromium command for inspection and tests. Test: `box/test.sh` (LAN http gets the flag with the right origin, with and without a trailing slash and a custom query; `127.0.0.1`, `localhost` and two `https://` URLs do not).
  - *Docs.* `box/README.md` opens with a topology table (backend on the box over loopback; HTTPS through `tailscale serve --bg --https=443 http://127.0.0.1:8080` or any reverse proxy; plain LAN HTTP with the kiosk flag and its caveats); README has a "Voice needs a secure context" paragraph; the Dockerfile comment says the same; the owner checklist's B1 says to open `http://localhost:8080`, not the Mac's LAN address.
- **Item 5, box provisioning.**
  - *tty1.* `corellia-kiosk.service` declares `Conflicts=getty@tty1.service` and `After=getty@tty1.service systemd-user-sessions.service network-online.target corellia-api.service`, with `TTYReset`/`TTYVHangup` and `-keeptty` on the Xorg command line. `provision.sh` removes the getty auto-login override earlier versions wrote (idempotent) and writes `/etc/X11/Xwrapper.config` (`allowed_users=anybody`) so a non-console user can start Xorg from a unit. The README lists what to check first if the screen stays black.
  - *Install.* `box/release.sh` builds the Linux amd64 static binary and the client into `box/release/` on the development machine with version and commit baked in; `provision.sh --release <dir>` installs them into `/opt/corellia`; with `--with-backend` and nothing installed it warns clearly. `/etc/corellia/api.env` is created `0600 root:root` with a comment on where the API key goes and to leave `CORELLIA_TZ` empty on the box.
- **Refusal.** `runtime.ErrRefused`; the Anthropic runtime returns it on `stop_reason: refusal` instead of emitting "I can't help with that one." as text. The session treats it as a failed turn whose words are the model's decline: the fragment ends in "…", "I can't help with that one." is its own speech piece and paragraph, the entry is `failed: true` so `historyLocked` skips it, and there is no error card (nothing broke). `describeFailure` maps it. Tests: `TestRefusalAndHTTPError` (runtime: fatal `ErrRefused`, no text), `TestRefusalIsSeparateAndOutOfHistory` (session: "Sure, the first step is to…" then the decline as two pieces, no card, next turn's history is `user:x,user:y`), the `describeFailure` table.
- **Prompt caching.** `prompt.System` is now the stable part only (identity, style, show_ui instructions, catalog, memory summary); `prompt.TurnContext` is the screen summary and the clock; `prompt.Full` joins them for the OpenAI-compatible and Hermes runtimes. The Anthropic request is: tools; system block with a breakpoint; history as plain text with a breakpoint on its last message; the current user message as two blocks, the turn context then the user's words, after both breakpoints. A third breakpoint moves along the request's last message (the user message in round 0, the latest tool results afterwards) so tool rounds within a turn hit too; it is removed before the next round appends, so the request never carries more than three. The history breakpoint's prefix is identical turn to turn (the context block is not stored, so the previous turn's user message reappears as plain text). Tests: `TestCacheBreakpointsAndTurnContext` (both rounds), the regenerated request goldens, `TestSystem` (no per-turn text in the static part).
- **`.dockerignore`** at the repository root (the build context): `.env` files except `.env.example`, `backend/data`, `backend/bin`, `node_modules`, `client/dist`, the Chromium libraries and test results, `.git`, `docs`, `box`, `adapters`. The Dockerfile's `COPY backend backend` and `COPY client client` no longer carry the owner's keys, transcript or the Mac's `node_modules`. Not built here (no Docker socket).
- **Watchdog.** `corellia-watchdog.sh` counts consecutive checks with `client_heartbeat_age_s: -1` and restarts the kiosk after `CORELLIA_WATCHDOG_MAX_NOCLIENT` of them (default 10, so five minutes at the 30 s interval, on top of the timer's two-minute boot delay); the counter resets on a restart and on any heartbeat. The env file path, state directory and `systemctl` are overridable for tests. Test: `box/test.sh` runs the script against a fake `/healthz` (healthy never restarts; a stale age restarts at once; `-1` restarts only after the grace, then the counter resets and a heartbeat resets it; unreachable restarts after `MAX_FAILS` and resets; a 503 counts as unreachable).
- **Local demo.** Greetings match whole words (`\b(hello|hi|hey|good morning|good evening)\b`), so "they said thanks" and "find a sushi place" fall through to "I heard: …"; weather is matched before the schedule, so "what's the weather today" is weather; a weather question about tomorrow, the week or a weekday is prefixed with "I only have current conditions on the local runtime."; the weather place comes from the gazetteer when a known city is named; "directions to the airport" says "I don't know that place on the local runtime. Here's Lisbon on the map; Navigate proposes directions to it." instead of announcing Lisbon as the answer. Tests: six new rows in the intent table.

## Design decisions

- **A session option, not `time.Local`.** Setting `time.Local` at boot would have fixed the prompt too, for every caller at once, but silently; `Options.Location` is explicit, testable, and leaves the process zone to the logger. The tools and the scheduler already took `loc`; the session was the one consumer that did not.
- **A refusal is a failed turn with its own words.** Reusing the failed status gives the fragment the Phase 14 treatment (ellipsis, separate speech, out of history) for free; the differences are the wording (no "Sorry, that didn't work on my side", because nothing did) and no error card. A new `TurnDone` status would have been a contract change for a path the fallbacks make rare.
- **Turn context in the user message, not a second system block.** A second system block after the breakpoint would still sit before the history in the prefix, so the history breakpoint could never hit. In the last user message it is after everything cached, and because the history is rebuilt from the transcript's plain text, the next turn's prefix does not contain it. The cost is that the model sees the clock as part of the user's message; the block is labelled ("Current date and time: …") and the instructions are unchanged.
- **Three breakpoints, one moving.** The system and history breakpoints serve across turns; the moving one serves within a turn (round 0 caches the user message for round 1; round n caches its tool results for round n+1). Lookups walk back from a breakpoint through earlier block boundaries, so removing the previous moving breakpoint loses nothing and keeps the count well under the API's four.
- **Kiosk flag and HTTPS both documented, HTTPS first.** The flag is the only thing that makes a plain LAN backend usable from the box, and it is scoped to one origin and one profile; it is still a workaround (the token is in clear on the LAN, a Mac browser gets no voice), so the README ranks the topologies and recommends the box's own backend or `tailscale serve`.
- **The kiosk unit owns tty1.** Of the review's two options, starting X from `.bash_profile` after a getty auto-login would have left the restart policy to bash; a unit with `Conflicts=getty@tty1.service` keeps `Restart=always` and the watchdog's `systemctl restart`.
- **Box scripts get a test without a box.** The two scripts with logic (kiosk flags, watchdog decisions) take their inputs from the environment and a fake `/healthz`, so `box/test.sh` can run them anywhere with bash, curl, jq and python3; it skips with a message where one is missing. Hardware-only questions (Xorg on the VT, `-keeptty`, GPU) are listed in the README as what to check first.

## How to run

As before: `pnpm install`, `pnpm -C client build`, `cd backend && go run ./cmd/api`, open http://localhost:8080. With `CORELLIA_TZ=Asia/Singapore` in `backend/.env` the model's clock, `get_time` and the clock card agree. On the local demo try "what's the weather today", "what's the weather in Lisbon tomorrow", "directions to the airport", "they said thanks". For the box, `./box/release.sh` then `box/README.md`.

## How to test

`pnpm check` (type-check, lint, 162 vitest tests, `go vet`, all 22 Go packages, `box/test.sh` with 11 checks, eight Playwright smoke tests in real Chromium) and `gofmt -l` on `backend/`. `go test ./internal/runtime/anthropic -update` regenerated the goldens once; the committed ones match.

Verified here: `pnpm check` green; `gofmt -l` clean; the goldens show the system block without the clock, a breakpoint on "Hello.", the context block before "show me the time", and the moving breakpoint on the tool results in rounds 2 and 3.

## Known gaps

- Nothing in `box/` has run on hardware. The tty1 ordering, `-keeptty`, `Xwrapper.config` and the GPU path are the first things to check; the README says how.
- The Docker image was not built (no socket); `.dockerignore` is checked by reading, not by a build.
- The kiosk flag makes a plain LAN origin secure for Chromium only; a Mac browser on the same URL still has no voice, and the token travels in clear. HTTPS is the lasting fix.
- Prompt caching is laid out correctly by the goldens; whether it hits in production (minimum cacheable prefix length, 5-minute TTL between turns) is for the owner's live run to confirm from the usage fields.
- The local demo still only parses; a weather question about tomorrow gets current conditions after a disclaimer, not a forecast.
